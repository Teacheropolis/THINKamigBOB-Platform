## 3. Common Correction Rules

Any future corrected candidate must:

- preserve the original source separately and retain its exact source path;
- receive a new candidate filename and checksum without silently overwriting the original;
- preserve the stable Activity Mission ID and require the Stable Identity and Version Authority to determine explicitly whether the corrected candidate is a non-substantive correction that retains version `1` or a substantive correction that creates version `2`;
- prohibit silently retaining version `1` after a substantive correction; the candidate filename, checksum, decision evidence, and later readiness record must state the approved version determination;
- remove setup-authoring instructions from the student-facing sequence;
- state the correct Grade, Goal, and Activity Mission consistently;
- contain only one Activity Mission and remove unrelated appended activity slides;
- use final student-facing language rather than author or template instructions;
- replace ambiguous slide-number evidence directions only after an activity-specific evidence-destination decision is explicitly approved for that Activity Mission;
- permit reuse of the existing Student Engineering Notebook / Evidence Portfolio contract only when Jennifer Williams explicitly confirms that the same contract, student action, teacher action, ownership boundary, and unavailable behavior apply to that Activity Mission; approval recorded for another activity is not inherited;
- distinguish required steps, choices, optional extensions, teacher-provided resources, and unavailable alternatives;
- identify required tools, materials, accounts, prerequisite work, and teacher preparation;
- state honest unavailable behavior when a required destination, account, permission, material, or prerequisite is missing;
- preserve contextual safety language only within its approved meaning;
- route substantive safety instructions to an assigned safety authority when applicable;
- provide readable and operable Chromebook directions; and
- avoid relying solely on color, tiny screenshots, icons, or unexplained visual demonstrations.

No correction may invent a destination, link, permission, source, prerequisite, material, safety rule, accessibility accommodation, or Platform integration.

## 5. Evidence Package Required Per Activity

Each corrected candidate must return with one evidence package containing:

| Evidence item | Required content |
|---|---|
| Candidate identity and version | Stable Activity Mission ID, source version, corrected-candidate filename, source filename, source path, checksum, and the Stable Identity and Version Authority’s explicit determination to retain version `1` for a non-substantive correction or create version `2` for a substantive correction |
| Curriculum confirmation | Correct Grade, Goal, title, intended student outcome, required steps, choices, and optional extensions |
| Directions inspection | Slide-by-slide confirmation that authoring instructions, conflicting relationships, ambiguous evidence references, duplicate content, and unrelated activities are resolved |
| Prep Guide reconciliation | Fact-by-fact tools, materials, accounts, prerequisites, and teacher preparation comparison |
| Evidence destination | Activity-specific approved destination, exact wording, teacher action, student action, ownership boundary, and unavailable behavior; reuse of the existing Student Engineering Notebook / Evidence Portfolio contract requires explicit approval for the reviewed Activity Mission |
| Safety context | Contextual versus substantive classification, supervision requirements, and concurrence evidence when applicable |
| Accessibility | Reading order, readable copy, non-color reliance, text alternatives, keyboard access, equivalent participation routes, and teacher-support requirements |
| Operational validation | Actual student Chromebook results for required destinations, permissions, editing, submission, return path, keyboard, touchpad, and failure behavior |
| Final result | `QUALIFIES FOR AVAILABILITY DECISION` or `FAIL CLOSED`, with every unresolved item listed |

An evidence package may reference existing approved evidence only when the referenced boundary is unchanged and directly applicable to that Activity Mission.

## 7. Required Sequence

For each activity:

1. record the Prep Guide row and source-deck comparison;
2. determine whether the planned correction is non-substantive and retains version `1` or substantive and creates version `2`, recording the decision before the corrected candidate is treated as a catalog version;
3. prepare a corrected candidate while preserving the original source and recording its approved version, filename, and checksum;
4. perform complete visual and directions-content reverification;
5. resolve and explicitly approve the activity-specific evidence-destination and unavailable-behavior contract; do not inherit another activity’s contract without explicit approval;
6. complete the applicable safety-context and accessibility review;
7. perform teacher-led physical Chromebook operational validation;
8. record a final readiness result by exact ID and explicitly determined version; and
9. return only fully qualifying records for a separate explicit availability decision.

Steps may be completed one activity at a time. One activity’s failure does not block correction or verification of another, but no activity inherits another activity’s approval.
