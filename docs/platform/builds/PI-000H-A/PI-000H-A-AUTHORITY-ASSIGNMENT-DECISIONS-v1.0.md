## 4. Verification Rules

- A real, accountable role, person, organization, or party must be explicitly supplied.
- The party and its accountability must be verified through explicit evidence appropriate to the scope.
- External parties must be separately verified; a URL, account, resource, employer, or organizational name is not assignment evidence.
- `NOT APPLICABLE` is permitted only where the entry expressly allows applicability review and an approved basis is supplied. It must not be used to bypass required concurrence.
- Generic labels—including developer, creator, owner, administrator, teacher, AI, THINKamigBOB, school, or district—cannot substitute for an accountable party unless the user later explicitly establishes and verifies that assignment.
- Authorship, repository ownership, commits, tool access, technical control, employment inference, conversation participation, prior approval participation, or resource access cannot establish authority.
- An assignment must include bounded scope, exclusions, concurrence, delegation limits, effective date, review/expiration, evidence, dependencies, and an explicit approval statement.
- Ambiguous, incomplete, expired, revoked, conflicting, or unverifiable submissions remain `UNASSIGNED`.
- No assignment becomes effective through documentation creation or review alone.
